# Reflection

The most deliberate design decision in this project was routing the loyalty-discount calculation through the Amazon Bedrock AgentCore Code Interpreter instead of letting the model do the arithmetic. The discount combines points redemption (capped at 50% of the order, in 500-point blocks), a tier-based percentage, and category-based earn rates. Language models are unreliable at multi-step arithmetic like this, so I wrapped the logic in a `calculate_loyalty_discount` tool that runs Python in an isolated sandbox and returns a JSON breakdown. This makes results deterministic and auditable. I also added a fallback that applies a simple tier discount if the sandbox call fails, so the agent degrades gracefully instead of breaking the conversation.

A concrete challenge came from the long-term memory hook. I used a Strands `MessageAddedEvent` hook to retrieve memories from AgentCore Memory and prepend them to the user’s message as “Customer Context,” and an `AfterInvocationEvent` hook to save each turn. The saved “user message” initially included the injected context, so retrieved memories were being re-stored as if the customer had said them, polluting the semantic and episodic strategies with duplicates. I resolved it by detecting the “Customer Context:” prefix and splitting it off, so only the customer’s original text is persisted. I also wrapped every memory call in try/except so a memory outage never blocks a support reply.

On the production side, security is the most pressing gap. The `initiate_refund` Lambda currently approves any refund automatically, trusting the order ID and amount supplied by the model, and `customer_id` is read directly from the request payload. In production I would verify that the order belongs to the authenticated customer (using identity from a verified token rather than the payload), enforce refund limits, and require human approval above a threshold. Similarly, the Code Interpreter script is built by interpolating the `tier` string into code, so I would validate inputs against an allowed set to prevent code injection. For monitoring, the project already includes the AWS OpenTelemetry distro, so traces can flow to CloudWatch; I would add alarms on tool error rates and on how often the discount fallback triggers. Finally, for cost and scalability, a new browser tool and MCP connection are created on every request, which I would replace with lazy initialization and reuse.
